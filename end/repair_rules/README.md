# 修理规则

机检没过时先跑这里的规则，规则改不动才叫模型。规则改成功**不占用** 3 次模型返修（`repairs`）。规则自己记在 `rule_repairs`。

资产、分镜、提示词封装，以及投喂机检（`check == machine`），都会先走这一层。

## 加一条规则

1. 在 `end/repair_rules/` 新建一个模块。
2. 写一个对象，带这些字段：
   - `id`：短名字，测试里会看到。
   - `stages`：`"asset"` / `"storyboard"` / `"feed"`。空元组表示每个阶段都看。
   - `match(report, stage, text, context)`：用机检报告里的稳定句子判断，不要拿整段报告做相等比较。
   - `apply(text, context)`：返回改完的全文。没有改动就返回原文。只改了别的文件时，原文照样返回，并设 `context["rule_touched"]=True`。`run_rules` 每条规则开始前清掉这个标记；看到它就当作这次有改动。
3. 能复用的函数不要重写。投喂看 `render_feed_text`、`align_feed_unit_headers`；资产看 `patch_asset_phrases`。
4. 在 `end/repair_rules/__init__.py` 的 `RULES` 里登记，放在已有规则后面。
5. 加测试：改写前能对上失败句；改写后这条失败不再出现；同一条再跑一次，正文不变。

`apply` 拿到的 `text` 是这一阶段的主稿：资产是 `assets.md`，分镜是 `分镜.md`，投喂是 `feed.md`。其它文件从 `context["folder"]` 读。

## 已有规则

`feed-unit-headers`：报告里有「未找到封装单元（## 【封装单元 N/M】格式）」。旧报告里的「未找到投喂单元」也算。稿子里已有 H3 或 Seedance 正文，但单元头缺失或不是 `## 【封装单元 N/M】`。先 `render_feed_text`，再按 `align_feed_unit_headers` 的切分把缺的头补成这个格式。旧稿里已经能切开的单元标题保持原词。

`storyboard-p453-sixq`：报告里有「缺六问」。分镜门禁重新渲染的是预演故事板，不是 `分镜.md`。规则改 `context["folder"]/_内部_/previs.md`；这份是空的，就改目录或 `_内部_` 里第一份有字的 `*-预演故事板.md`。改完写回 `previs.md`，并覆盖找到的 `*-预演故事板.md` 副本。`分镜.md` 原样返回，用 `rule_touched` 记这次已修理，不占 `repairs`。读不到预演稿、或没有一格要改，则不动文件。

六问词用 `check_p45.py` 的 `SIX`，不另抄一份。先在原句里补近义词：面对面→面对面正对，微侧→微侧身，相对→相对面朝，静止→静止停住，下垂→下垂停住，平稳踩→平稳踩停，并肩而立→并肩站立；只有背影、且没有站/在/位于时，在「背影」后补「站在」。还缺的键再补短句：朝哪 `，身体正对前方`；做什么 `，动作停住`；谁在哪 `，人物站在画面中`；看哪 `，视线望向画面前方`；镜头在哪 `，镜头在平视中景`；光从哪来 `，光从侧上方照来`。句尾若连着「看图…」，短句补在它前面。缺 2 项是 FAIL，缺 1 项是 WARN；一旦跑起来，两样一起补。
