# 语义关卡和历史副本

审查记录在项目目录的 `reviews.json`。通过只对当时的剧本、上下文和最终提交内容有效。

## 活动稿和旧媒体

重跑、作废出片步骤、撤下成片文件之前，会先把将要移出活动路径的文件复制到：

`data/web_projects/<项目 id>/history/<时间>-<原因>/`

同目录有 `manifest.json`，列出相对路径、字节数和 sha256。活动路径上的旧稿、旧图、旧片会被拿掉，避免下一次运行把它们当成当前结果。`history/` 里的副本不会被这次清理删掉。

查看某一份旧稿：打开对应时间目录，按 `manifest.json` 里的 `path` 读文件。要拿回来看，把该文件复制出来即可。这不是一套版本库，没有自动回放。

## 提交前核对

出片提交读取磁盘上的 `spec.json` 和当前尾帧有没有真正截到，拼出本次要送出的提示词和绑定（镜号、模式、是否带上一镜末帧、参考图 id）。该组合必须已经出现在这次审查的 `prompt_hashes` 里，并且 `source_hash` 仍等于磁盘上的剧本和下游稿。

核对在项目锁里读两次。两次不一致就拒绝提交。锁放开之后到 HTTP 发出之前，仍有一段盖不住的窗口；下载完成、记成当前结果之前会再读一次磁盘，变了就把新文件归档到 `history/`，不把它标成这一步的完成结果。
